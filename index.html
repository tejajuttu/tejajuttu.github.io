forward deployed engineer

noun

An engineer who works inside a customer’s business instead of behind a ticket queue — close enough to see how the work really gets done, and technical enough to build the system that changes it.

Lead, in my case, means I shape the architecture, write code on the hard parts, and coach the engineers doing the day-to-day building. It doesn’t mean I stopped building.

At Eliza

June 2026 – now

Yes, that ELIZA. The 1960s chatbot walked so enterprise AI could run.

What I do at Eliza

Eliza embeds forward deployed engineers inside companies to build production AI systems — and to leave the team able to run and extend them. My job is to make sure what we build is technically sound, fits how the customer actually works, and makes our engineers better along the way.

The problems

Usually a workflow that eats expert time: people searching across documents and systems, reconciling data by hand, or answering the same questions again and again. The work is finding the part AI should do — and being clear about the part it shouldn’t.

Decisions I work on

  • Which parts need retrieval, which need an agent with tools, and which should just be ordinary code.
  • How the system gets its context: ingestion, permissions, search quality.
  • What “good enough” means before we build — evaluation sets, relevance metrics, acceptance thresholds.
  • What we are not building yet, and saying so early.

Helping FDEs grow

I pair on the hardest part of a build, review designs before they harden, and raise risks early with a recommendation attached. When something works twice, we write it down as a playbook or a reusable building block, so the next team starts further ahead.

Multimodal AI · Media & entertainment

Scene-level search for video libraries

A media library is searchable only by what someone typed into its metadata. We made the footage itself searchable — by what’s on screen and what’s said — and used that to drive new content.

My part
Retrieval architecture combining video understanding, audio parsing and metadata enrichment, and the agents built on top for highlights, summary podcasts and articles.
The hard part
Lining up three kinds of signal on one timeline, so a search returns the right scene rather than the right file.
Read the full story: scene-level search for video libraries

Agentic retrieval · Energy

An agent that answers from the company’s own documents

The goal was to take routine questions off subject-matter experts’ plates by giving people an assistant that searches, checks and cites the company’s own material.

My part
Ingestion pipelines and the search layer over unstructured, semi-structured and API data; ReAct-style tool use with guardrails; embedding tuning and reranking.
The hard part
Retrieval quality. An agent is only as good as the context it pulls, so most of the effort went into what gets indexed and how results are ranked.

Video AI · Alliance work with NVIDIA

Reusable starting points on NVIDIA’s video search blueprint

I adapted NVIDIA’s Video Search and Summarization (VSS) blueprint into repeatable starting points for client pursuits, so a team could show a working system in a new domain rather than a slide about one.

  • Sports highlights
  • Corporate security alerting

Things I keep relearning

Passing UAT is not adoption.

A system can clear every acceptance test and still go unused. Before we build, I want to know who opens it on an ordinary Tuesday, and why.

Check the context before blaming the model.

Most bad answers I’ve debugged came from the wrong context, not the wrong model. Better embeddings and a reranker are often cheaper than a bigger LLM.

Write it down the second time.

The first time is a project. The second time is a pattern — worth a template, so the next team doesn’t start from zero.
